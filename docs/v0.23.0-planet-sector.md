# v0.23.0 planet sector indexing

Deploy Sqitch change `planet-sector-20261110` before starting the sector-aware
sync-state writer, and start that writer before the chain's v0.23.0 upgrade.
The change is additive and compatible with the previous writer.

- `structs.planet.sector` is a non-null smallint with default zero and a check
  constraint allowing only `0`, `127`, `999`, and `44`.
- Zero means legacy/unassigned. The SQL migration does not guess assignments.
  The chain's backfill emits normal Planet events with the authoritative sectors.
- `view.planet.sector` is appended to the existing optimized join-based view.
  Deployment preserves its OID, owner, grants, and existing column order.
- Table-level read grants already cover the new column. No new write permission
  is granted. This change exposes SQL data; webapp model/API/UI work is separate.

The matching writer decodes quoted uint64 and numeric JSON sectors, writes the
field on insert and conflict update, and includes it in the change predicate.
A sector-only backfill event therefore updates an existing row; identical replay
makes no redundant planet update. Historical events without sector map to zero,
as the complete source record did before v0.23.0. Normal ordered replay remains
required; this is not a special out-of-order merge rule.

The writer's mandatory schema check requires the sector columns before ingestion,
including when optional doctor checks are disabled. Apply the database migration
rather than manually adding a column. If upgrade events were indexed by an older
writer, replay the missed events through the normal supported recovery procedure;
restarting at the current tip alone cannot recover already discarded fields.

Revert requires stopping/rolling back the new writer first. It explicitly drops
and recreates the view without CASCADE, preserving its owner and table-level ACL;
dependent views must be rolled back first. Dropping the sector column discards
its data. Export it first if rollback must preserve assignments.

Validation on November 10, 2026 used a disposable PostgreSQL 18/Timescale instance
with a schema-only copy of the local database. Deploy and Sqitch verify scripts,
`tests/planet_sector_lifecycle.py`, and the real Go Planet handler tests passed.
The lifecycle test covers legacy defaults, sector constraints, view readback,
view identity/grants on deploy, revert and redeploy. Handler tests cover legacy
input, all three sectors, sector-only updates, repeated events, and name updates.
No migrations or writer restarts were applied to the running stack.
